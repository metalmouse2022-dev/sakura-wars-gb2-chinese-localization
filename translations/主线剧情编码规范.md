# 樱花大战GB2 主线剧情编码规范（已破解）

> 依据：项目根目录 `re_extract_story.py`（22:57 新版提取器）+ 对渲染引擎的反汇编
> 结论：**引擎原生支持汉字，不需要改代码**，只需把字模写入对应槽位。

---

## 一、编码规则

| 字节 | 含义 |
|---|---|
| `0x00` | 字符串结束 |
| `0x0D` | 换行 |
| `0x08` | 玩家名占位（显示为「大神」） |
| `0x01 XX` | 符号页第 XX 项 |
| `0x02 XX` ~ `0x07 XX` | **汉字页 H=2..7 的第 XX 项** |
| `0x4F` ~ `0xFE` | 单字节假名 / 符号（H=0） |
| `0xFF 0xFF` | 「！」 |

### 符号页（0x01 + XX）

```
00 /   01 '   02 "   03 (   04 )   05 [   06 ]   07 『  08 』
09 +   0A -   0B ×   0C ÷   0D =   0E %   0F ♪   10 _   11 <
12 >   13 →   14 々   15 :   16 ○   17 Ex  18 ♥
```

### 单字节页（H=0，0x4F 起）

按五十音顺序排列，含小写、浊音、半浊音，末尾接片假名与标点：

```
0x4F ぁ  0x50 あ  0x51 ぃ  0x52 い  0x53 ぅ  0x54 う  0x55 ぇ  0x56 え  0x57 ぉ  0x58 お
0x59 か  0x5A が  0x5B き  0x5C ぎ  0x5D く  0x5E ぐ  0x5F け  0x60 げ  0x61 こ  0x62 ご
...
0xA0 を  0xA1 ん  0xA2 ァ  0xA3 ア ... 0xF9 ？ 0xFA ！ 0xFB ー 0xFC ～ 0xFD 「 0xFE 」
```

## 二、汉字槽位容量

- 页号 H = 2 ~ 7，共 **6 页**
- 每页 256 项（低字节 0x00 ~ 0xFF）
- **合计 1536 个汉字槽位**
- 现有 `kanji_table` 仅使用约 **130 个**（游戏原版实际用到的那部分）
- **剩余约 1400 个空槽可直接用于汉化**

## 三、渲染引擎（反汇编确认）

| 地址 | 作用 |
|---|---|
| ROM `0x0606BB`（Bank 0x18:0x46BB） | 文本解码主循环 |
| 其中 `CP $FF` | 0xFF → 画「！」后继续 |
| 其中 `CP $10` / `JR NC` | ≥0x10 → 单字节，H 保持，L=A |
| 其中 `CP $08` / `JR C` | <0x08 → 双字节，H=A，再读一字节为 L |
| ROM `0x001B00` | 把 H:L 存入字符缓冲 `$C6C3` |
| ROM `0x00187B` | 从缓冲取字符，`CP $08` 判断双字节 |
| ROM `0x001B24` | 分发：`CP $02` —— H<2 走 8×8 假名/符号，H≥2 走汉字路径 |
| ROM `0x001B59` | 字模数据区起点（H=0 的 8×8 点阵） |

## 四、下一步

1. **算出汉字字模地址公式**（由 `0x1B24` 之后的分支推导 H≥2 时的取模方式）
2. **批量生成字模**：按译文用字渲染 8×8（或 16×16）点阵，写入 ROM 空闲区
   - ROM 现有 70 个近乎全空的 bank，合计 **1,115 KB**，可放 14 万+ 8×8 字模，空间充裕
3. **建立映射表**：汉字 ↔ (H, L)，供编码与回填使用
4. **翻译并回填**：译文按上述规则编码写入 `story/chapter_*.txt` 对应 ROM 偏移
