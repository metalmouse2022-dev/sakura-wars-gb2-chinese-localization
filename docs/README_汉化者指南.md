# 《樱花大战 GB2》GBC 简体中文汉化工程指南

> 本指南根据现有工程脚本与 `docs/sakura_taisen_gb2_localization_postmortem.md` 整理。技术地址、覆盖数量和最终 ROM 校验值目前沿用工程复盘中的记录，重新构建并复核后再视为当前发布事实。

## 项目内容

本工程为《樱花大战 GB2：雷霆作战》（Game Boy Color）的简体中文 ROM 补丁工程。主剧情和非剧情文本使用不同字库与注入路径：主剧情由 `inject_fixed2.py` 处理，地下城、战斗、探索及系统等 8×8 文本由 `inject_dungeon.py` 处理；`build_all.py` 按顺序调用这两个入口并输出最终 ROM。

主要目录：

- `translations/story/`：第 1 至 14 章主线文本。
- `translations/dungeon/`：地下城与出击文本、逐 Bank 底稿和相关数据。
- `translations/battle/`、`translations/exploration/`、`translations/system/`：战斗、探索及系统文本。
- `fonts/`：构建所需字体文件。两款字体均从 GitHub 获取：Ark-Pixel 来自 [TakWolf/ark-pixel-font](https://github.com/TakWolf/ark-pixel-font)，字体采用 SIL Open Font License 1.1，工程内附有许可文本；小点阵字体来自 [pixel-font-legacy/xiaodianzhen-pixel-font](https://github.com/pixel-font-legacy/xiaodianzhen-pixel-font)，但该仓库说明其原始字体来源、作者及版权不明。GitHub 可下载不等于字体本身有再分发授权；发布前须取得明确授权或替换字体。Windows 宋体不应打包分发。
- `outputs/`：本机构建产物目录。ROM、存档和模拟器状态文件不得作为普通源码发布内容。
- `docs/`：工程说明、编码规范、复盘和维护记录。

现有 `translations/汉化翻译报告.md` 和 `translations/主线剧情编码规范.md` 是较早阶段记录。报告标注日期为 2026-10-17，部分覆盖数量与后续复盘/脚本描述不一致；编码规范中仍有待确认事项，也与现在的双注入器方案有差异。阅读时应把它们作为历史材料，现行规则以 `inject_fixed2.py`、`inject_dungeon.py` 和最新可复现验证为准，确认差异后再统一文档。

根目录还包含逆向/注入脚本、模拟器 RAM/SAV、截图、调试脚本及备份。当前工程目录内未找到脚本所需的原版 `.gbc` ROM；`outputs/` 中有两份 4MB 汉化 ROM。它们用途不同，不能仅凭文件扩展名判断后删除；源码和必要资源要保留，临时产物应在确认可重建后再清理。

## 环境与构建

### 已从脚本确认的依赖

- Python 3（`build_all.py` 使用当前 Python 解释器启动子脚本）。
- Pillow（`PIL`）和 `zhconv`，用于字模绘制和简繁转换。
- Windows 系统字体 `C:/Windows/Fonts/simsun.ttc` 被主线注入脚本引用。
- `fonts/xiaodianzhen/xiaodianzhen-8px.ttf` 被地下城注入脚本引用。
- PyBoy 用于无头模拟器 QA；它不由 `build_all.py` 显式调用，是否为构建依赖需以完整脚本和实际环境复核。

### 必需输入

- 合法取得、与脚本预期一致的日版原始 ROM：`Sakura Taisen GB2 - Thunderbolt Sakusen (Japan)(Sega)(32Mb).gbc`。
- 完整翻译底稿、脚本和获准使用的字体资源。

原始 ROM 与汉化成品 ROM 受版权保护，不应上传到公开仓库。工程应只保存补丁生成所需的自制脚本、文本和依法可分发资源；如果改为发布补丁，也应确认补丁格式及分发方式符合权利人和平台规则。

本次检查没有在工程目录中找到原版 ROM，因此当前副本无法直接从零构建。必须由使用者合法准备对应版本的原版 ROM，再按脚本要求放在工程根目录；不要把它提交到 Git。

工程随附说明与 [上游仓库的字体许可说明](https://github.com/pixel-font-legacy/xiaodianzhen-pixel-font/blob/master/LICENSE-FONT.md) 均指出，小点阵字体原始来源、作者及版权不明；该仓库的 MIT 许可适用于构建程序，不能据此推定字体文件获准再分发。应先找到权利人/授权或替换为明确可分发的字体，再考虑公开构建流程。Windows 宋体由操作系统提供，不应随仓库复制。

### 可复现构建步骤

1. 将工程源码放在一个独立目录，保留 `translations/`、`fonts/` 和构建脚本的相对目录结构。
2. 在该目录安装 Python、Pillow、zhconv，并按字体许可要求准备字体。若主线脚本固定引用 Windows 宋体，需使用 Windows 或先调整为可配置字体路径。
3. 将合法取得的日版 ROM 放到脚本指定的位置。确认输入 ROM 的版本/哈希与工程记录一致；不要把个人 ROM 放进提交。
4. 从工程根目录运行 `python build_all.py`。脚本先运行主线注入，再运行地下城注入，预期产物为 `outputs/Sakura Taisen GB2 - Chinese_Fixed.gbc`。
5. 保存构建日志、输出大小和 SHA-256；确认两步均成功，并核对 ROM Header 与 Global Checksum。
6. 使用模拟器完成画面与流程抽查，再运行已有无头 QA 脚本检查关键剧情和 UI。QA 脚本/测试 ROM/存档需与发布源码分开管理。

现有复盘记录的最终 ROM 大小为 4,194,304 字节，SHA-256 为 `27EFB1F9F3793B43EB793AFE16F23E4680C464048AB550746ECB32DA0E0FA8A8`，Header Checksum 为 `0xDA`、Global Checksum 为 `0xD4FB`。这些值是历史记录，不代表当前目录中的 ROM 已重新校验。

## 翻译与编码约定

- 修改底稿后先检查原文条目数量、控制码、跳转/选项 ID、换行和槽位字节上限。不能把显示文本与后续脚本控制字节合并覆盖。
- 主线与 8×8 非剧情文本走不同编码和字模管线；新增文本先判断属于哪种脚本，再改相应底稿。
- 保留起名/菜单依赖的原生单字节假名区。复盘记录指出，H=0 假名与部分系统 UI 必须保护，不能被动态汉字映射占用。
- 选项、换页和弹窗中的连续空行可能有布局语义；不要折叠连续换行。
- 地下城简体字重定向应避开所有底稿已使用的 Shift-JIS 字符，避免覆盖原字模并造成全局错字。
- 翻译内容需统一简体字形、术语和标点；每次更新都重新跑字节长度检查及构建。
- ROM 地址、Bank 编号、压缩流长度和指针都是版本相关数据。换 ROM 版本时必须重新定位和验证，不能照抄地址。

## 已记录的关键问题与解决思路

1. **限时选项导致剧情跳过**：复盘记录将原因归结为注入器覆盖选项 ID/固定槽位。应保护控制结构，仅在计算出的文本槽位内定长写入，并通过剧情分支实测。
2. **起名界面假名乱码**：动态汉字误占单字节假名区。应保护 H=0 原生 UI 字符，并回归检查姓名、性别、是/否等界面。
3. **缺字或方框**：字体覆盖不足或编码映射缺字。应检查字形生成结果与映射冲突；复盘中记录了 Ark-Pixel 与系统字体回退方案。
4. **压缩图形超出原位置**：新图块数据可能膨胀并覆盖邻接资源。写回前必须比较压缩长度与可用空间；若改为搬迁数据流，需验证所有 Bank/指针/调用点。
5. **UI 切页后瓦片错位**：屏幕外 Tilemap 行可能是备用模板。应同时检查显示行和缓冲模板行，并检查 VRAM Bank 与属性表。
6. **字模被重定向池污染**：候选 Shift-JIS 槽可能仍被翻译文本使用。候选池需由完整翻译集生成黑名单后再分配。

以上为已有复盘结论的摘要；新维护者应以当前脚本实现、原始 ROM 对照和实机/模拟器证据复核，不应只依赖文字记录。

## 验证清单

- [ ] 从原始 ROM 全量构建成功，且再次构建得到相同哈希。
- [ ] 检查 Header Checksum、Global Checksum、文件尺寸及 ROM 版本。
- [ ] 主线剧情覆盖各章节、分支和限时选项；未跳过对白，选项 ID/跳转正常。
- [ ] 检查姓名输入、假名/汉字切页、删除/确定、存档读档及标题菜单。
- [ ] 检查地下城、战斗、探索、状态/策略/背包 UI；重点查乱码、缺字、溢出与瓦片残影。
- [ ] 记录模拟器名称/版本、测试步骤、存档状态、截图、结果和待修问题。
- [ ] 公开发布前扫描密钥、个人路径、存档/用户数据、ROM/字体版权内容和大文件。

## 已知限制与待复核事项

- 目前脚本直接引用 Windows 宋体路径，构建对 Windows 字体环境有依赖；建议改为显式配置并记录字体授权。
- 工程根目录混有大量调试截图、`.ram`/`.sav`、临时脚本、备份和 ROM；本次审计未删除任何项目文件，因为源目录在当前会话中只读且若干文件的保留用途尚未逐一核实。
- 复盘文档含有个人绝对路径引用，公开前需改成仓库相对路径。
- 工程中的 ROM、存档、第三方字体和可能来自商业游戏的资源需要逐项核实许可；在核实前应从公开提交中排除。
- 工程路径当前没有 Git 元数据、远程仓库或提交历史，因此无法检查既有分支/未提交变更，也不能安全地推送。
- 目录中暂未发现 `doc/`，现有记录位于 `docs/`；需确定以 `docs/` 作为正式文档目录。

## 维护与贡献流程

1. 先备份并确认原始 ROM 版本；不直接修改唯一的原始文件。
2. 每项翻译/代码改动尽量独立提交，提交说明写明受影响模块和验证结果。
3. 保留可再生成的构建脚本与翻译源文件；排除 ROM、存档、RAM 快照、缓存、临时截图、个人日志与备份副本。
4. 更新问题复盘时区分“已验证”“推断”“待验证”，补充复现步骤、证据、修复和回归结果。
5. 在发布前由维护者复查文件清单、许可证、Git diff、敏感信息和仓库可见性；仅向确认有权访问的目标仓库推送。
